# Обзор источников данных: почему генератор, а не готовый набор

Проверка выполнена 20.08.2026. Цель — выяснить, можно ли заменить синтетические данные
реальной выгрузкой 1С или открытым розничным набором, и зафиксировать результат, чтобы
выбор генератора не выглядел выбором из удобства.

## 1. Выгрузки 1С в открытом доступе

Искались готовые файлы обмена (JSON/XML) из «1С:Розница» с продажами по торговым точкам.

Найдено следующее:

| Что найдено | Что это | Пригодность |
| --- | --- | --- |
| Обработки выгрузки «Розница 2.х → Бухгалтерия 3.0» через JSON (`Prixod.json`, `RasxodNal.json`, `RasxodKarta.json`) | Внешние обработки, публикуются на Infostart | Инструмент, а не данные: нужна лицензионная 1С и своя информационная база |
| Обработки выгрузки документов в XML (в том числе штатная «Выгрузка и загрузка данных XML») | Средство переноса между базами | То же: без информационной базы выгружать нечего |
| Универсальные обработки выгрузки в Excel/CSV/JSON/XML | Платные публикации маркетплейса | То же |

**Вывод.** Готовых наборов файлов обмена в открытом доступе нет, и это ожидаемо: файл
обмена содержит первичные документы конкретного предприятия — коммерческую информацию,
которую не публикуют. Открыто описан только *формат*: состав полей отчёта о розничных
продажах, приходных накладных и справочников. Именно это и использовано: контракт обмена
в работе воспроизводит документированный состав объектов и полей (см. `docs/1c-objects.md`
и `docs/exchange-protocol.md`), а данные внутри контракта генерируются.

## 2. Открытые розничные наборы данных

Проверялось, нельзя ли взять сторонний открытый набор и преобразовать его в контракт обмена.

**Warehouse and Retail Sales** (Montgomery County, Maryland; открыт без авторизации,
CSV/JSON/XML). Фактический состав полей проверен запросом к API набора:

```
calendar_year, cal_month_num, supplier, item_code, item_description,
item_type, rtl_sales, rtl_transfers, whs_sales
```

Не подходит: это **месячные агрегаты по товарам и поставщикам**. Нет торговых точек —
то есть нет объекта анализа; нет себестоимости — то есть нельзя посчитать ни валовую,
ни операционную прибыль; нет документов реализации и возвратов с датами.

**Наборы Kaggle** (например, «Synthetic Retail Dataset — 1.2M Transactions», «Retail Sales
Forecast Dataset 2026», «Sales Records»). Ближе по структуре: есть разрез
«точка × товар × дата», в части наборов есть `cost_price`. Но:

- они сами синтетические (это указано в описании), поэтому достоверность данных
  не повышается — меняется лишь автор генерации;
- лицензии части наборов не определены («Unknown»), что для работы, к которой прилагается
  воспроизводимый код, неудобно;
- структура не соответствует контракту 1С: нет ссылочных идентификаторов объектов
  (`ref`), нет документов реализации и возврата как сущностей, нет служебной части пакета
  обмена — то есть проверять на них загрузку по контракту всё равно нельзя;
- скачивание требует авторизации, из-за чего разворачивание проекта «одной командой»
  перестало бы работать.

## 3. Принятое решение

Данные формирует собственный генератор (`docs/adr/0005-synthetic-data-generator.md`),
потому что он даёт то, чего нет ни в одном найденном наборе:

1. **соответствие контракту обмена** — файлы проходят ту же проверку схемой и правилами,
   что и настоящая выгрузка;
2. **управляемые сценарии** — полное отсутствие себестоимости, короткая история,
   высокая доля возвратов, 16 намеренно некорректных пакетов. Ни один
   открытый набор не содержит нарушений контракта «по заказу», а без них нельзя показать,
   как механизм обмена отклоняет плохие данные;
3. **воспроизводимость** — фиксированное зерно и манифест: у проверяющего получаются
   ровно те же файлы и те же числа в отчётах.

Ограничение зафиксировано открыто: показатели, которых в выгрузке нет (ставка накладных
расходов, доля себестоимости по категориям), помечены как моделируемые и в интерфейсе,
и в программном интерфейсе, и в тексте работы (`docs/data-provenance.md`).

## 4. Что изменится при доступе к настоящей базе

Заменяется только источник пакетов: каталог файлов обмена — на выгрузку из
информационной базы (или веб-сервис). Правила проверки, сопоставление объектов, расчёт
показателей и сверка контрольных сумм остаются без изменений; доля моделируемой
себестоимости при этом снижается, что видно в тех же показателях витрины
(`cost_accounting_share_pct`).

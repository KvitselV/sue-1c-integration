Обмен можно запустить и без веб-приложения: задание `sue.jobs.exchange` использует те же
источник, валидатор, загрузчик и сверку, добавляя отчёт файлом и код возврата
для планировщика.

## Слои и их границы

| Слой | Модуль | Отвечает за | Не знает о |
|------|--------|-------------|-----------|
| Источник | `sue.adapter_1c` | чтение пакета, контроль размера, хеш содержимого | базе данных |
| Валидация | `sue.adapter_1c.validator` | соответствие схеме и бизнес-правилам | способе хранения |
| Загрузка | `sue.etl.pipeline` | идемпотентная запись, аудит, транзакционность | расчёте показателей |
| Домен | `sue.domain` | KPI, происхождение, витрина, сверка | HTTP и шаблонах |
| Представление | `sue.api`, `sue.web` | контракты ответов, страницы, контроль доступа | источнике данных |
| Задания | `sue.jobs` | регламентный обмен для планировщика | HTTP и шаблонах |
| Инфраструктура | `sue.config`, `sue.db`, `sue.money`, `sue.logging_config` | настройки, сессии, арифметика, журнал | предметной логике |

Границы соблюдаются буквально: домен принимает `Session` и не обращается к настройкам
HTTP, а адаптер источника не импортирует модели. Поэтому замена файлового обмена на
подключение к 1С требует одной новой реализации `OneCSource`.

## Ключевые решения

**Источник за интерфейсом.** `OneCSource` возвращает `Batch` — полезную нагрузку
вместе с хешем, размером и метаданными происхождения. ETL и домен одинаково работают
с файлом на диске и с загруженным по HTTP пакетом.

**Валидация до записи, приёмка «всё или ничего».** Пакет проверяется целиком: сначала
JSON Schema (структура), затем правила приёмника (ссылочная целостность, знаки, точность,
границы периода, дубли внутри пакета). Любое нарушение уровня `error` — даже в одном
документе — отклоняет пакет полностью: статус `failed`, данные не изменяются, все
нарушения перечислены в `etl_errors`. Частичная приёмка сделала бы сверку контрольных
сумм источника и приёмника заведомо расходящейся, поэтому от неё отказались осознанно.
Статус `partial` остаётся возможным только на этапе записи: документ, ссылающийся
на торговую точку, отсутствующую в справочнике приёмника, отклоняется защитной проверкой
загрузчика (штатная валидация до этого не допускает, поскольку требует самодостаточности
пакета).

**Идемпотентность по `source_ref`.** Повторная загрузка обновляет существующие записи.
Строки документа перед вставкой удаляются и по идентификатору документа, и по
`source_ref` строки — иначе перенос строки между документами в новой выгрузке дал бы дубль.

**Аудит отдельной транзакцией.** Запись `etl_runs` фиксируется до загрузки данных,
поэтому сбой оставляет след: прогон помечается `failed`, ошибки пишутся в `etl_errors`,
данные не изменяются. «Зависших» прогонов в статусе `started` не остаётся.

**Точность денег.** Суммы хранятся целым числом копеек, количества — тысячных долей;
`Decimal` используется в домене. Это позволяет агрегировать средствами СУБД
и получать одинаковый результат на SQLite и PostgreSQL
([ADR 0002](adr/0002-integer-minor-units-for-money.md)).

**Происхождение как часть значения.** Каждый показатель — `ProvenanceValue` с меткой
источника и пояснением методики; показатель без источника создать нельзя
([ADR 0004](adr/0004-explicit-data-provenance.md)).

**Одна агрегация вместо запроса на точку.** Показатели по всем точкам считаются
запросом `GROUP BY store_id, category` с индексами `(store_id, sale_date)`
и `(store_id, doc_date)`.

**Схема только миграциями.** Развёртывание — `alembic upgrade head`; `create_all`
остался для тестов. Соответствие миграций моделям проверяет `alembic check` в CI.

**Работа без интернета.** Chart.js и шрифты лежат в `src/sue/web/static/vendor/`;
отсутствие внешних ссылок в разметке проверяется тестом.

## Структура кода

```text
src/sue/
  adapter_1c/     источник данных и валидация контракта
  etl/            конвейер загрузки с аудитом
  domain/         рентабельность, сверка, происхождение, витрина, аналитика страниц
  api/            маршруты, схемы ответов, обработка ошибок, безопасность путей
  web/            шаблоны Jinja2 и статические файлы
  datagen/        генератор синтетических пакетов обмена и CLI
  db/             модели, engine, сессии
  config.py       настройки с проверкой при старте
  money.py        точная арифметика денег и количеств
  i18n.py         русские подписи интерфейса
migrations/       ревизии Alembic
schemas/          JSON Schema контракта обмена
tests/            unit / integration / api / ui
```

## Что можно расширить без переделки

| Задача | Что потребуется |
|--------|-----------------|
| Подключение к живой базе 1С | реализовать `ODataSource.iter_batches` |
| Другая СУБД | строка подключения в `SUE_DATABASE_URL` и ревизия Alembic |
| Новый показатель | `ProvenanceValue` в `sue.domain.profitability` и поле в схеме ответа |
| Другие параметры моделирования | `SUE_OVERHEAD_RATE`, файлы в `data/fixtures/modeled/`, таблица `model_params` |

# Сопоставление контракта обмена и модели СУЭ

Версия контракта: **2.0**. Денежные величины приходят в рублях, хранятся в копейках;
количества приходят в единицах, хранятся в тысячных долях (см.
[ADR 0002](adr/0002-integer-minor-units-for-money.md)).

| Поле контракта | Поле СУЭ | Тип в БД | Обязательно | Правило преобразования |
|----------------|----------|----------|-------------|------------------------|
| `ref` | `source_ref` | `varchar(64)`, уникально | да | бизнес-ключ, ключ идемпотентности |
| `code` | `code` | `varchar(64)` | да | без изменений |
| `name` | `name` | `varchar(255)` | да | без изменений |
| `city` | `city` | `varchar(128)` | нет | без изменений |
| `format` | `store_format` | `varchar(64)` | нет | без изменений |
| `isActive` | `is_active` | `boolean` | нет | по умолчанию `true` |

## Строки документа → `sale_lines`

| Поле контракта | Поле СУЭ | Тип в БД | Обязательно | Правило преобразования |
|----------------|----------|----------|-------------|------------------------|
| `ref` | `source_ref` | `varchar(64)`, уникально | да | бизнес-ключ |
| `productRef` | `product_id` | FK на `products` | да | поиск по `products.source_ref` |
| `quantity` | `quantity_milli` | `bigint` | да | × 1000; для возвратов знак отрицательный |
| `amount` | `revenue_kopecks` | `bigint` | да | × 100; для возвратов знак отрицательный |
| `costAmount` | `cost_accounting_kopecks` | `bigint`, допускает NULL | нет | × 100; NULL означает, что себестоимость будет смоделирована |
| `discountAmount` | — | — | нет | не хранится: уже вычтена из `amount`, повторный учёт исказил бы выручку |
| — | `store_id`, `sale_date`, `doc_type` | — | — | денормализация из документа для агрегации одним запросом |

## Знак величин при возврате

В контракте суммы и количества **всегда положительные**; знак определяется типом
документа. Приёмник записывает строки возврата с отрицательными `quantity_milli`
и `revenue_kopecks`, поэтому выручка получается суммированием без исключений
и особых случаев в запросах. В отчёте возвраты дополнительно показываются отдельно
(`gross_revenue` и `returns`), чтобы уменьшение выручки было видно, а не скрыто в итоге.

## Что приёмник добавляет от себя

| Величина | Откуда | Метка происхождения |
|----------|--------|---------------------|
| Себестоимость строк без `costAmount` | `amount` × доля себестоимости категории | `modeled` |
| Накладные расходы точки | выручка × `SUE_OVERHEAD_RATE` | `modeled` |
| Валовая и операционная прибыль, маржа | расчёт из показателей выше | `derived` |

Производные показатели **не хранятся** в базе: они вычисляются в
`src/sue/domain/profitability.py` при запросе. Это исключает расхождение между
сохранённым значением и данными, из которых оно получено. Методика —
[`profitability-method.md`](profitability-method.md), происхождение —
[`data-provenance.md`](data-provenance.md).

# СУЭ — механизм интеграции данных формата 1С:Розница

Прототип механизма интеграции учётных данных формата **1С:Розница** в корпоративную
систему управления эффективностью (СУЭ) с расчётом рентабельности торговых точек.

Реализованы: контракт файлового обмена с версионированием, адаптер источника, ETL
с аудитом и идемпотентностью, сверка контрольных сумм «источник ↔ СУЭ», расчёт
рентабельности с явным происхождением каждого показателя.

> Подключение к действующей информационной базе 1С не входит в текущую реализацию.
> Обмен выполняется по файловому контракту, структурно совместимому с объектами
> 1С:Розница; для подключения по REST/OData предусмотрен интерфейс `ODataSource`.

## Быстрый старт

Требования: Python 3.11 или новее. Для контейнерного запуска нужны Docker и
Docker Compose.

### Windows

```powershell
.\tasks.ps1 install     # .venv, зависимости, хуки pre-commit
.\tasks.ps1 seed        # миграции + генерация фикстур + загрузка штатным ETL
.\tasks.ps1 run         # http://127.0.0.1:8000
```

Одной командой: `.\scripts\run_demo.ps1`

### Linux / macOS

```bash
make install
make seed
make run
```

Одной командой: `./scripts/run_demo.sh`

### Docker (PostgreSQL + приложение)

```bash
docker compose up --build -d
docker compose exec api alembic upgrade head
docker compose exec api python scripts/seed.py     # осознанный отдельный шаг
```

Прод-контейнер применяет миграции, но **не** наполняет БД демонстрационными данными.

Контур ближе к промышленному (JSON-журнал, запрет импорта по пути, `SUE_APP_ENV=production`):

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up --build -d
```

## Данные

Данные синтетические, генерируются детерминированно: один `--seed` даёт побайтово
одинаковый результат. Рядом с пакетами пишется `manifest.json` с параметрами
генерации и контрольными суммами.

```bash
python -m sue.datagen --list                        # доступные сценарии
python -m sue.datagen --out data/fixtures           # сценарии по умолчанию
python -m sue.datagen --out data/fixtures --with-large   # + объёмный набор
```

| Сценарий | Назначение |
|----------|-----------|
| `accounting` | основной демонстрационный набор, смешанная себестоимость |
| `no_cost` | себестоимость отсутствует полностью → показатель полностью моделируется |
| `short_history` | новая точка с короткой историей — расчёт на неполном периоде |
| `returns_heavy` | повышенная доля возвратов покупателей |
| `large` | около 130 тыс. строк для проверки производительности ETL (в репозиторий не коммитится) |
| `invalid/` | 16 некорректных пакетов, по одному нарушению на правило приёмки |

## Происхождение показателей

Каждое значение в интерфейсе и в API помечено источником — это ключевое требование
к прозрачности расчёта.

| Метка | Значение |
|-------|----------|
| `accounting` | взято из учётной выгрузки (поле контракта обмена) |
| `modeled` | смоделировано по заданному параметру (накладные расходы; себестоимость при отсутствии `costAmount`) |
| `derived` | получено расчётом из показателей выше (валовая и операционная прибыль, рентабельность) |
| `accounting+modeled` | смешанный случай с указанием долей |

Методика: [`docs/profitability-method.md`](docs/profitability-method.md),
[`docs/data-provenance.md`](docs/data-provenance.md).

## Переменные окружения

Все настройки читаются с префиксом `SUE_` из окружения или из `.env`
(шаблон — [`.env.example`](.env.example)). Некорректное значение приводит к отказу
на старте, а не к неверным расчётам.

| Переменная | По умолчанию | Назначение |
|-----------|--------------|-----------|
| `SUE_APP_ENV` | `local` | `local`, `test` или `production` |
| `SUE_LOG_LEVEL` | `INFO` | Уровень журналирования |
| `SUE_LOG_JSON` | `false` | Структурный журнал в формате JSON |
| `SUE_DATABASE_URL` | `sqlite:///data/sue.db` | Строка подключения (SQLite или PostgreSQL) |
| `SUE_SQL_ECHO` | `false` | Печатать SQL-запросы |
| `SUE_FIXTURES_DIR` | `data/fixtures` | Каталог пакетов обмена; загрузка по пути **ограничена им** |
| `SUE_SCHEMA_PATH` | `schemas/1c_retail_exchange.schema.json` | Путь к JSON Schema контракта |
| `SUE_MAX_UPLOAD_BYTES` | `33554432` | Предел размера загружаемого файла (32 МБ) |
| `SUE_MAX_BATCH_DOCUMENTS` | `200000` | Предел числа документов в пакете |
| `SUE_MAX_ERRORS_PER_RUN` | `500` | Сколько ошибок сохранять на один прогон |
| `SUE_ETL_CHUNK_SIZE` | `5000` | Размер порции при массовой вставке |
| `SUE_ALLOW_LOCAL_PATH_IMPORT` | `true` | Разрешить импорт по имени файла внутри каталога фикстур |
| `SUE_REPORTS_DIR` | `data/reports` | Куда задание регламентного обмена пишет отчёты |
| `SUE_API_KEY` | пусто | Ключ `X-API-Key`; пустое значение — барьер выключен |
| `SUE_PROTECT_READ` | `false` | Требовать ключ и на чтении (требует заданного `SUE_API_KEY`) |
| `SUE_OVERHEAD_RATE` | `0.12` | Моделируемая доля накладных расходов от выручки |
| `SUE_DEFAULT_COST_RATIO` | `0.65` | Моделируемая доля себестоимости при отсутствии `costAmount` |
| `SUE_MARGIN_TARGET_PCT` | `28.0` | Целевая операционная рентабельность, % (оценка «норма») |
| `SUE_MARGIN_WARN_PCT` | `27.0` | Порог предупреждения, % (ниже — «ниже нормы») |
| `SUE_API_PAGE_SIZE` | `50` | Размер страницы по умолчанию |
| `SUE_API_MAX_PAGE_SIZE` | `500` | Предел размера страницы |

## Ограничения

1. **Живая 1С не подключена.** Реализован файловый обмен по контракту, структурно
   совместимому с объектами 1С:Розница. Подключение к ИБ через OData оставлено
   точкой расширения (`ODataSource`) и явно не реализовано.
2. **Данные синтетические.** Порядок величин и структура правдоподобны, но это не
   выгрузка реального предприятия. Каждый пакет сопровождается `manifest.json`.
   Поиск альтернатив — готовых выгрузок 1С и открытых розничных наборов — выполнен
   и задокументирован: [`docs/data-sources-review.md`](docs/data-sources-review.md).
3. **Накладные расходы всегда моделируются** по параметру `SUE_OVERHEAD_RATE`:
   в учётной выгрузке 1С:Розница их нет. Показатель помечен `modeled`.
4. **Себестоимость моделируется частично** — только для строк без `costAmount`;
   доли учётной и смоделированной части выводятся в интерфейсе.
5. **Контроль доступа минимальный** — один общий ключ на изменяющие операции
   (`SUE_API_KEY`), при желании и на чтение (`SUE_PROTECT_READ`). Ролевой модели и единого
   входа организации нет: это прототип аналитического контура, а не многопользовательская
   система. Веб-интерфейс ключом не закрывается и в промышленном контуре выносится
   за обратный прокси; при заданном ключе формы загрузки на `/ui/etl` скрываются, и данные
   принимаются API или регламентным заданием.
6. **Оценка рентабельности задаётся настройкой.** Пороги «норма / внимание / ниже нормы» —
   управленческий ориентир (`SUE_MARGIN_TARGET_PCT`, `SUE_MARGIN_WARN_PCT`), а не учётная
   величина; значения по умолчанию подобраны под демонстрационный набор.
